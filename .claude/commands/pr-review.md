# PR 리뷰 대응

PR에 달린 리뷰 코멘트를 읽고 분류·수정·답변한다.
**모든 답변 초안은 한글로 작성**한다.

## 사용법

`/pr-review` — 현재 브랜치 PR의 리뷰 코멘트 처리
`/pr-review $ARGUMENTS` — 리뷰 내용 직접 붙여넣기

## 실행 순서

### 1. 리뷰 수집

- `gh` CLI 사용 가능 시: `gh pr view --comments` + `gh api repos/{owner}/{repo}/pulls/{pr-number}/comments` 로 코멘트 수집
- `gh` CLI 불가 시: `$ARGUMENTS`로 받은 리뷰 내용 그대로 사용

### 2. 리뷰 분류

각 코멘트를 아래 유형으로 분류하여 표로 출력:

| 유형 | 설명 | 처리 방법 |
|------|------|-----------|
| 코드 수정 필요 | 버그, 로직 오류, 개선 요청 | 즉시 수정 |
| 질문/설명 요청 | 구현 의도, 설계 이유 질문 | 답변 초안 작성 |
| 칭찬/nit | 사소한 스타일 의견, 칭찬 | 스킵 (목록에만 표시) |
| 논의 필요 | 설계 방향, 트레이드오프 등 | 별도 표시 후 사용자 확인 요청 |

분류 결과를 요약 테이블로 먼저 출력한 후 진행한다.

### 3. 수정 작업 (코드 수정 필요 항목)

각 수정 항목에 대해:
1. 리뷰어 코멘트 원문 표시
2. 해당 파일/라인 읽기
3. 수정 전/후 코드 diff 출력
4. 사용자 승인 후 실제 파일 수정

수정 시 프로젝트 규칙 준수 여부 재확인:
- `any` 타입 사용하지 않았는가
- `@/` 절대경로를 사용하는가
- 하드코딩 문자열 대신 `t()` 사용하는가
- 비즈니스 로직이 `hooks/`에 분리되어 있는가
- 컴포넌트 책임 분리가 지켜지는가 (UI 렌더링만)

### 4. 답변 초안 (질문/설명 요청 항목)

코드를 확인한 후 답변 초안을 작성한다:
- 해당 코드의 실제 구현을 근거로 답변
- 추측이 아닌 코드 기반 설명
- 필요 시 코드 스니펫 포함

답변 형식:
```
> [리뷰어 코멘트 원문]

[답변 내용]
```

- `gh` CLI 사용 가능 시: 사용자 승인 후 `gh pr comment`로 직접 게시
- `gh` CLI 불가 시: 복사 가능한 형태로 출력

### 5. 논의 필요 항목

사용자에게 의견을 물어본 후, 합의된 방향에 따라 수정 또는 답변 작성한다.

### 6. 완료 처리

모든 항목 처리 후:
- 처리 결과 요약 테이블 출력 (항목별 완료/스킵/보류 상태)
- 코드 수정이 있었으면 커밋 안내
- 미처리 항목이 있으면 별도 표시
